# galette-sail-riscv

A Rocq comparison of two RISC-V semantics:

| | Model | Where |
|---|---|---|
| **L3** | Galette's L3-derived RV64 model (`Galette.HOL.examples.l3_machine_code.riscv.model.riscv`, step `riscv_step.NextRISCV`), which Galette's Pancake compiler-correctness theorem `pan_to_target_compile_semantics` is stated over | `deps/galette` |
| **Sail** | The official Sail RISC-V model, translated to Rocq by Sail's Rocq backend (`rocq-sail-riscv`, RV64) | `deps/sail-riscv` |

**Goal.** Formal equivalence for what matters to compiled Pancake programs: the
observable behaviour defined by Galette's `machine_sem` (a port of CakeML's).
The plan follows the Lean development
[riscv-im-compare](https://github.com/flamingoponderado/riscv-im-compare):

1. a state relation between L3 states and Sail states;
2. single-step simulation for every instruction that Galette's RISC-V encoder
   emits (37 instruction kinds), under explicit side conditions (privilege
   mode, address translation off, alignment, PMP, interrupts...);
3. a generic `machine_sem` simulation theorem;
4. transfer of `pan_to_target_compile_semantics` to a machine configuration
   whose processor is the Sail model.

Status: work in progress.
- Done: the toolchain, the generated model, and a sequential interpreter
  that runs Sail's instruction monad on a concrete state (with smoke tests).
- Next: the state relation and the per-instruction simulation; see
  `DESIGN.md`.

## Building

The Rocq output of sail-riscv needs `rocq-sail-stdpp`, which requires Rocq
< 9.3, so this project uses a dedicated opam switch with Rocq 9.2 and Sail
from git (sail-riscv master needs rems-project/sail#1757, which is not yet
released):

    opam switch create galette-sail ocaml-base-compiler.5.2.1
    opam repo add rocq-released https://rocq-prover.org/opam/released --switch=galette-sail
    opam pin add --switch=galette-sail rocq-core 9.2.0
    opam pin add --switch=galette-sail rocq-runtime 9.2.0
    opam pin add --switch=galette-sail -k git \
      "git+https://github.com/rems-project/sail.git#2ba321281cea18485f783da05c8a147a45d6b980"
    opam install --switch=galette-sail rocq-stdlib rocq-sail-stdpp

    git submodule update --init
    eval $(opam env --switch=galette-sail)
    dune build          # dune >= 3.24 (Galette's dune-project requires it)

- `sail/` holds the Rocq files generated from `deps/sail-riscv`.
  `scripts/gen-sail.sh` regenerates them, and `scripts/gen-sail.sh --check`
  checks that they are up to date.
- `theories/Regfile.v` is generated by `scripts/gen-regfile.py`.
- `deps/galette` is built as part of the dune workspace (theory `Galette`).

## Layout

| Path | Contents |
|---|---|
| `sail/` | generated Sail model (`rv64d.v`, `rv64d_types.v`, `riscv_extras.v`), theory `Riscv` |
| `theories/Regfile.v` | register file, one field per register family |
| `theories/Interp.v` | sequential interpreter for Sail's interaction-tree monad |
| `tests/RunAdd.v` | smoke tests: Sail decodes and executes `add` under the interpreter |
| `DESIGN.md` | plan: relation, step simulation, `machine_sem` transfer |
